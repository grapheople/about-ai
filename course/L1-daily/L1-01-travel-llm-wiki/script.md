## [S01] 서버 개발자 — 포털기업에서 스타트업까지 🖼
안녕하세요.
저는 2014년에 대형 포털 회사에 신입으로 들어갔습니다.
그다음엔 커머스 플랫폼 회사로 옮겼고요.
올해로 12년차 개발자예요.
주로 서비스 뒤에서 돌아가는 서버를 만들어 왔습니다.

2021년, 코로나가 한창이던 때 대기업을 떠났어요.
학교 선후배들과 건강 플랫폼을 만드는 스타트업에 합류했습니다.
어떤 기술을 써도 괜찮은, 자유로운 분위기였어요.
그래서 새로 나온 AI 도구도 바로 써 볼 수 있었습니다.
이때 익혔던 AI활용 경력을 기반으로 지금은 대기업 산하의 헬스케어 플랫폼 회사에서 커머스 플랫폼 개발을 담당하고 있습니다.

## [S02] 2022년 — AI에게 맡긴 건 함수 몇 줄 🖼
2022년쯤, 깃허브 코파일럿이라는 AI 코딩 도우미를 처음 써 봤어요.
GPT-3를 개량한 모델로 돌아가는 도구였죠.
그런데 저는 AI를 다루는 데 서툴렀고, AI를 다 믿지도 못했어요.
그래서 함수 안의 몇 줄 정도만 도움을 받았습니다.

## [S03] 2023년 GPT-4 — 쓸 만해졌지만, 맡기진 못했다 🖼
2023년, GPT-4가 나왔습니다.
성능이 확 좋아져서, 업무에 꽤 괜찮은 도움을 받았어요.
그래도 일을 통째로 맡기지는 못했습니다.
[강사 확인] 결국 마지막엔 제가 다 확인하고 고쳐야 했거든요.

## [S04] 2025년 Claude Code — 판이 바뀌었다 🖼
그리고 2025년 초, Claude Code가 나왔습니다.
여기서부터 판이 완전히 바뀌기 시작했어요.
제 체감으로는, 코딩만큼은 AI가 사람 실력을 넘어섰습니다.
지금 저는 코드를 한 줄도 직접 짜지 않아요. 개발은 전부 AI가 합니다.
제가 하는 일은 무엇을 만들지 정하고, AI가 만든 걸 판단하는 거예요.

## [S05] AI를 쓰는 법도 몇 달마다 바뀐다 🖼
도구만 바뀐 게 아닙니다. AI를 쓰는 방법도 계속 바뀌고 있어요.
Claude Code에는 스킬, 플러그인 같은 강력한 확장 기능이 붙었고요.
처음엔 질문을 잘 하는 "프롬프트 엔지니어링"이 중요했습니다.
다음은 AI에게 필요한 자료를 챙겨 주는 "컨텍스트 엔지니어링",
AI가 일할 작업 환경을 갖춰 주는 "하네스 엔지니어링",
사람이 매번 시키지 않아도 알아서 반복하게 만드는 "루프 엔지니어링",
AI가 한 일을 자동으로 채점하는 "이밸 엔지니어링",
요즘은 여러 AI를 한 팀처럼 엮는 "그래프 엔지니어링"까지 나왔어요.
[강조] 몇 달마다 새 이름이 생길 만큼 빠릅니다.

## [S06] 그래서 고민했다 — 변하지 않는 가치는 무엇인가 🖼
이렇게 빨리 바뀌니까, 고민이 하나 생겼습니다.
오늘 익힌 방법이 몇 달 뒤엔 낡은 게 되잖아요.
그럼 이 변화 속에서도 변하지 않는 가치는 뭘까?
[강사 확인] 제가 찾은 답 중 하나는 "내가 쌓아 온 지식과 맥락"이었습니다.
도구는 바뀌어도, 내가 정리해 둔 지식은 남으니까요.

## [S07] 카파시가 제안한 답 — LLM 위키 🖼
그러다 눈에 들어온 글이 있습니다.
안드레 카파시라는 AI 연구자가 공개한 "LLM 위키"라는 아이디어예요.
카파시는 OpenAI를 함께 세운 사람이고, 올해 5월에는 Claude를 만드는 Anthropic에 합류했습니다.
이게 어떤 건지, 오늘은 제 여행 이야기로 보여 드릴게요.

## [S08] 표지 — 기억하는 여행 계획 만들기 🖼
[화면: 표지 슬라이드]

오늘은 Claude와 Obsidian으로 "기억하는 여행 계획"을 만들어 볼 거예요.
먼저 LLM 위키가 뭔지, 왜 써야 하는지 딱 3분만 이야기할게요.

## [S09] 채팅으로 계획을 짜면, 대화가 끝나는 순간 사라진다 🖼
보통 AI로 여행 계획 짤 때 어떻게 하세요?
채팅창에 "도쿄 3박 4일 짜 줘" 하죠.
꽤 그럴듯한 답이 나옵니다.
그런데 며칠 뒤에 "아, 아이가 6살이라 많이 못 걷는데" 하고 다시 물어보면요?
처음부터 다시 설명해야 합니다.
대화는 끝나면 사라지거든요.

## [S10] 위키는 쌓이고, 바뀔 때 같이 바뀐다 🖼
AI한테 문서를 올려서 물어보는 방식도 있죠.
그것도 질문할 때마다 문서를 처음부터 다시 뒤져서 답을 만듭니다.
아무것도 쌓이지 않아요.

LLM 위키는 다릅니다.
AI가 자료를 읽고, 정리해서, 파일로 남겨 둡니다.
장소마다 페이지가 하나씩 생기고, 페이지끼리 서로 연결돼요.
그리고 새로운 정보가 들어오면, 관련된 페이지를 전부 같이 고칩니다.
[강조] 대화는 사라지지만, 위키는 쌓입니다.

## [S11] 사람은 질문하고, AI는 정리한다 🖼
카파시 글의 핵심은 역할 분담이에요.
사람은 어떤 자료를 넣을지 고르고, 질문하고, 방향을 정합니다.
요약하고, 연결하고, 고치는 귀찮은 일은 전부 AI가 합니다.
사람들이 위키를 만들다 포기하는 이유가 바로 이 정리하는 일이 귀찮아서인데, AI는 지치지 않으니까요.

그리고 이걸 눈으로 보기 위해 Obsidian이라는 노트 앱을 씁니다.
카파시는 이렇게 비유했어요. "Obsidian은 작업 화면이고, AI는 일하는 사람이고, 위키는 결과물이다."

## [S12] 오늘 할 것과 준비물 🖼
그럼 이 위키를 여행 계획으로 직접 만들어 볼게요.
오늘 영상이 끝나면 여러분 컴퓨터에 나만의 여행 위키가 하나 생깁니다.
순서는 세 단계예요.
첫째, 프로그램 세 개를 설치합니다.
둘째, AI와 함께 위키 규칙을 만듭니다.
셋째, 실제로 여행 계획을 짜고, 바꿔 봅니다.

준비물은 맥 컴퓨터, 그리고 Claude 유료 플랜입니다.
촬영 시점 기준으로 무료 플랜에서는 오늘 쓰는 Claude Code가 안 되고, 월 20달러짜리 Pro 플랜부터 됩니다.
윈도우를 쓰시는 분은 설명란에 따로 정리해 뒀어요.

자, 이제 설치해 볼게요.

## [S13] 설치 ① Obsidian — 무료, 드래그 한 번 📽
[화면: 브라우저에서 obsidian.md 접속]

먼저 Obsidian입니다. 개인용이든 업무용이든 무료예요.
홈페이지에서 맥용 다운로드를 누르고,
[화면: 설치 파일 열기 → Applications 폴더로 드래그]
열리는 창에서 Obsidian 아이콘을 응용 프로그램 폴더로 끌어다 놓으면 끝입니다.

[화면: (리허설 때 실제 화면 확인) Obsidian 실행 → 새 볼트 만들기 → 이름 "travel-wiki" → 위치 선택 → 생성]
처음 실행하면 "볼트"를 만들라고 나와요. 볼트는 그냥 노트를 담는 폴더라고 생각하시면 됩니다.
이름은 travel-wiki로 할게요.

## [S14] 설치 ② 생애 첫 터미널 — 여기가 유일한 터미널 구간입니다 📽
다음은 Claude Code입니다. 여기서 터미널이라는 걸 처음 열게 될 거예요.
[강조] 검은 창이 무서워 보여도 괜찮습니다. 오늘 터미널은 이 구간이 처음이자 마지막이에요.

[화면: Cmd + Space → "Terminal" 입력 → Enter]
키보드에서 커맨드와 스페이스를 같이 누르고, "Terminal"이라고 치고 엔터.
커서가 깜빡이는 창이 뜨죠? 이게 터미널입니다. 컴퓨터에 글로 명령하는 곳이에요.

## [S15] 명령 한 줄 붙여넣기 → claude → 로그인 📽
[화면: 설명란의 설치 명령 복사 → 터미널에 Cmd + V → Enter]
`curl -fsSL https://claude.ai/install.sh | bash`

설명란에 있는 이 한 줄을 복사해서, 터미널에 붙여넣고 엔터를 누릅니다.
[강조] 설치 중에는 아무 표시가 안 나와요. 멈춘 게 아니니까 창을 닫지 말고 기다리세요.
[화면: "Claude Code successfully installed!" 표시]
이 문구가 나오면 성공입니다.

[화면: `claude` 입력 → Enter → 브라우저 로그인 → 터미널로 돌아와 환영 화면]
이제 claude라고 치고 엔터.
브라우저가 열리면 Claude 계정으로 로그인하세요.
환영 화면이 보이면 준비 끝입니다. 터미널은 이제 닫으셔도 돼요.

[화면 자막: "command not found: claude"가 나오면 → 터미널 창을 새로 열고 다시 시도 (설명란 참고)]

## [S16] 설치 ③ Claudian — Obsidian 안에 Claude를 넣는다 📽
[화면: Obsidian → 설정 → 커뮤니티 플러그인 → (제한 모드가 켜져 있으면 끄기 — 리허설 때 실제 화면 확인) → 둘러보기 → "Claudian" 검색 → 설치 → 활성화]

마지막으로 Claudian입니다. Obsidian 안에 Claude를 넣어 주는 플러그인이에요.
Obsidian 설정에서 커뮤니티 플러그인으로 들어가서, 둘러보기를 누르고, Claudian을 검색합니다.
설치, 그리고 활성화.

[화면: 왼쪽 리본의 Claudian 아이콘 클릭 → 오른쪽에 채팅 창 열림]
이제 오른쪽에 Claude와 대화하는 창이 생겼습니다.
왼쪽에는 노트, 오른쪽에는 AI. 이 화면이 오늘의 작업실이에요.

## [S17] AI와 함께 위키 규칙 만들기 📽
이제 진짜 재미있는 부분입니다.
아까 말한 카파시의 글, 사실 이 글은 프로그램이 아니에요. 아이디어를 적어 둔 글입니다.
카파시가 의도한 사용법은 간단해요. 이 글을 AI한테 주고, "내 용도에 맞게 같이 만들자"고 하는 거죠.

[화면: Claudian 창에 입력]
> https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f
> 이 글을 읽고, 이 볼트를 내 여행 계획용 LLM 위키로 만들어 줘. 필요한 건 나한테 물어봐.

[화면: Claude의 질문에 답하는 장면 — 여행 스타일, 하루에 얼마나 걷는지, 좋아하는 것·싫어하는 것 (빨리감기)]
Claude가 이것저것 물어봅니다. 저는 여행할 때 빡빡한 일정을 싫어하고, 먹는 걸 좋아한다고 답했어요.

[화면: 왼쪽 파일 목록에 CLAUDE.md, 폴더, 프로필 파일이 생기는 장면]
보세요. 위키 규칙을 적은 CLAUDE.md, 폴더 구조, 그리고 제 여행 취향을 적은 프로필이 생겼습니다.

[강조] 여러분 화면은 저랑 조금 다를 거예요. 정상입니다. 여러분 취향에 맞춰 만든 거니까요.

## [S18] 자료를 넣으면, 페이지가 생기고 서로 연결된다 📽
이제 위키에 자료를 넣어 볼게요.

[화면: Claudian 입력]
> 이 문서를 위키에 추가해 줘: https://ko.wikipedia.org/wiki/아사쿠사
> 이것도: https://ko.wikipedia.org/wiki/긴자

[화면: 응답 대기 빨리감기 → 새 페이지들이 생기는 파일 목록]
Claude가 문서를 읽고, 요약 페이지를 만들고, 도쿄 페이지, 동네 페이지, 명소 페이지를 따로 만들어서 서로 연결합니다.

[화면: 그래프 뷰 열기 → 점과 선이 생긴 모습]
그래프 뷰로 보면, 점들이 생기고 선으로 이어진 게 보이죠.
자료를 넣을수록 이 그물이 촘촘해집니다.

## [S19] "6월에 가족이랑 3박 4일 도쿄" — 위키를 근거로 계획이 나온다 📽
자, 이제 여행 계획을 짜 달라고 해 볼게요.

[화면: Claudian 입력]
> 6월에 가족이랑 3박 4일 도쿄 여행 계획 짜줘. 동행자는 6세 아이와 아내 둘이야.

[화면: 응답 대기 빨리감기 → 일정 파일 열기]
일정 파일이 생겼습니다.
[화면: 일정에서 아이 관련 부분 하이라이트]
여기 보시면, 6살 아이가 있으니까 하루에 걷는 거리를 줄이고, 중간중간 쉬는 시간을 넣었어요.
제가 프로필에 적어 둔 취향도 반영돼 있고요.
그리고 이 일정은 아까 넣은 아사쿠사, 긴자 페이지를 근거로 짜였습니다. 링크를 누르면 바로 따라가 볼 수 있어요.
